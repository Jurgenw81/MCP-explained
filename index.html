Model Context Protocol

The USB-C for AI applications.

MCP is an open protocol for connecting AI hosts to external tools and data through a consistent client–server interface. Instead of building a custom integration for every model × service combination, you expose capabilities once and let compatible hosts discover and use them.

01 — The idea

Why MCP exists

LLMs are useful on their own, but real applications need context and actions: read a database, search docs, inspect GitHub, call an internal API, or trigger a workflow. MCP standardizes the boundary between the AI application and those capabilities.

WITHOUT MCP

N × M integrations

Every AI host needs bespoke glue for every data source and tool. Authentication, schemas, discovery, errors, and transport get reinvented.

WITH MCP

One shared contract

An MCP server advertises what it can do. An MCP client understands the protocol. The host can connect the two without knowing the implementation details.

RESULT

Composable capabilities

Servers can focus on domain logic while hosts focus on user experience, model orchestration, permissions, and deciding when a capability should be used.

02 — Architecture

Host → Client → Server

The host is the AI application. It creates MCP clients, which maintain protocol connections to MCP servers. A server can be a local process or a remote service.

AI Host

Chat or agent app. Owns the model interaction, UX, user consent, and orchestration.

→
MCP Client

Speaks MCP, negotiates capabilities, discovers primitives, sends requests and receives results.

→
MCP Server

Exposes domain-specific tools, resources, and prompts over a standard transport.

Important: MCP does not replace your API or your model. It is the interoperability layer that describes and transports context and actions between AI applications and capability providers.
03 — Core primitives

What a server exposes

TOOLS

Do something

Callable functions with typed inputs. Examples: calculate a value, create an issue, query a service, or run a workflow. Think “model-invokable action.”

RESOURCES

Read something

Addressable context such as files, records, docs, or generated data. Resources let clients retrieve information that can be supplied to the model.

PROMPTS

Guide an interaction

Reusable prompt templates published by a server. They package domain-specific interaction patterns and parameters for clients to present or use.

The protocol also covers capability negotiation and lifecycle behavior. Transports carry the messages; current Python SDK documentation supports stdio, Streamable HTTP, and SSE.
04 — Request lifecycle

What happens when the model uses a tool?

Connect & initialize

The client and server establish a connection and negotiate supported protocol capabilities.

Discover

The client asks for available tools/resources/prompts and receives names, descriptions, and schemas.

Model decides

The host gives relevant capability descriptions to the model. The model may request a tool call with structured arguments.

Host authorizes & executes

The host applies its own policy/consent flow, then the client sends the call to the MCP server.

Result returns

The server executes domain logic and returns structured content. The host can feed that result back into the model conversation.

05 — Working Python example

Build an MCP server in minutes

This example uses the official MCP Python SDK v2. It exposes a calculator tool, a dynamic resource, and a reusable prompt. Python 3.10+ is required by the current SDK docs.

server.py
from mcp.server.fastmcp import FastMCP

# Create the MCP server
mcp = FastMCP("YouTube MCP Demo")

@mcp.tool()
def add(a: int, b: int) -> int:
    """Add two integers and return the result."""
    return a + b

@mcp.resource("greeting://{name}")
def greeting(name: str) -> str:
    """Return a greeting as an MCP resource."""
    return f"Hello, {name}! This came from an MCP resource."

@mcp.prompt()
def explain_topic(topic: str) -> str:
    """Create a reusable explanation prompt."""
    return f"Explain {topic} clearly, with one analogy and one example."

if __name__ == "__main__":
    mcp.run()
